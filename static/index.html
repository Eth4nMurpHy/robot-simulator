Model

Two loops share one intersection X. R1 and R2 serve stations A1–A4, R3 and R4 serve B1–B4; each carries one task at a time. Charging bays C1 and C2 hang off X through H. Only one robot may be inside X at a time, with a buffer on each side, and only one robot per bay.

Times are in seconds, battery in percentage points. Loading and unloading cost 0.5% each. Waiting in a queue drains the battery; idling between jobs does not.

Command plans

Write or import plans under My strategy; edge lengths are changed in Map editor. A plan is a list of {robot_id, at, action, …} entries. Actions are execute_task, move_to, charge and wait. They run exactly as written: a busy robot, an overlapping booking or an unsafe battery level rejects the whole plan. Nothing is rescheduled or charged automatically, and tasks without a command stay unexecuted.

Built-in schedulers

FCFS takes tasks in release order and picks the robot that would finish first. Deadline takes the earliest due date first, priority breaking ties. Joint greedy looks at the next eight tasks and minimises completion + 3·priority·lateness + 0.5·wait + 2·energy. All three are heuristics; they charge to 95% when the battery gets low.

Metrics

Makespan is the last delivery (for command plans, the end of the last command). Average wait is intersection plus charger queueing per task. Utilisation is busy time over makespan.

Loop edges are not exclusive, so this is a resource model, not a collision model. There is no global optimisation, nonlinear charging or live order injection.
