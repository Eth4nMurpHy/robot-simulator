\begin{abstract}
\noindent 四台机器人在两条固定的有向环路上执行取送任务，同时共用一个交叉口和数量有限的充电位。
由于等待同样消耗电量，任务顺序、资源排队与电池状态相互耦合。本项目在一个有界整数调度模型中联合决定
机器人分配、访问顺序、交叉口时隙、充电位选择和充电量：联合贪心（Joint Greedy）给出初始调度，CP-SAT
在此基础上搜索改进，滚动时域版本仅利用已释放的任务重新规划。返回的动作轨迹均经过先后顺序、资源容量和电池
安全检查。在存档的 40 任务、10 个随机种子实验中，CP-SAT 相对 FCFS 将平均综合目标 $J$ 降低 53.2\pct，
完工时间（makespan）缩短 28.3\pct（FCFS 版本 75afc09，CP-SAT 版本 c87fb9f；8 个工作线程，CP-SAT 时限
120\,s）。在另一个随机种子为 6 的 12 任务实例上，CP-SAT 在单线程、30\,s 墙钟上限和 0.5 确定性预算下
将完工时间缩短 30.4\pct。短预算批量运行未发现超出联合贪心的改进。总体而言，这些结果表明，
对任务、交叉口和充电进行一体化调度，有望提升固定路线多机器人系统的性能。

\medskip\noindent\textbf{关键词：}多机器人调度；充电调度；约束规划；交叉口预约；滚动时域；离散事件仿真。
\end{abstract}

\section{引言}

\subsection{研究背景}

多机器人系统广泛用于自动化制造和仓储环境中的运输与物料搬运。调度首先涉及任务分配，即决定由哪台机器人
执行哪项任务以及机器人之间如何协同。Athira 等~\cite{athira2025mrta} 综述了此类任务分配问题，以及
协同与不确定性的处理方法。

在自动导引车（AGV）系统中，任务分配还会受到共享交通资源的制约。Li、Fan 和 Jia~\cite{li2024conflict}
在自动化集装箱码头中将动态任务分配与无冲突路径规划相结合，要求车辆不得同时占用同一网络区域。若调度时忽略此类
冲突，车辆在实际相遇时可能导致方案不可行。

电池约束带来了第二重耦合。充电设施稀缺时，充电会与运输争夺车辆时间和充电位容量；因此 Li 等~\cite{li2025chargers}
在充电位数量有限的条件下对 AGV 任务与充电进行联合调度。在这些研究的基础上，本项目研究固定路线多机器人
系统中任务执行、交叉口预约与充电决策的联合调度。与模型各组成部分相关的方法将在后续相应章节
（第~\ref{sec:model}~节和第~\ref{sec:methods}~节）中进一步讨论。

\subsection{系统概述与问题描述}

本项目考虑一个多机器人取送系统：四台机器人在两条固定的有向环路上运行，每条环路分配两台机器人；每项运输
任务要求一台机器人在同一环路的两个站点之间取货并送货。两条环路共用一个交叉口，交叉口同一时刻只能容纳一台
机器人。机器人还共用一个最多含两个充电位的充电区，每个充电位同一时刻只服务一台机器人。

调度问题是确定由哪台机器人执行每项任务、任务的执行顺序、机器人何时通过共享交叉口，以及何时充电、充多少电。
这些决策必须满足任务先后顺序、资源容量和电池安全约束。目标是最小化由完工时间、按优先级加权的迟到时间、
资源等待时间和能耗构成的综合指标。

\subsection{研究动机与调度难点}

在本项目中，四台机器人服务两条固定环路，但共用交叉口 X 和充电区。任务分配结果直接改变机器人到达取货站、
X 和充电位的时刻；由此产生的排队不仅推迟任务完成，还会持续消耗电量。因此，完工时间、迟到、等待和能耗均受同一组分配与时序决策
的共同影响。

例如，当一台机器人（如 R1）接到下一项任务时，其电量看似足以完成取货和送货，却可能不足以在之后安全到达
充电位，调度器就必须先安排充电。为到达充电区，机器人需要预约并通过共享交叉口；之后可能还要等待空闲的
充电位，排队期间继续耗电。充电完成后，机器人必须再次预约交叉口才能返回所属环路。这些额外的移动和等待
可能推迟后续任务，使其错过截止时间。因此，任务调度、资源预约和电池状态必须联合考虑。

\subsection{研究问题}

基于上述耦合关系，本项目研究以下问题：
\begin{itemize}
\item \textbf{RQ1：}在任务、地图、初始荷电状态（SOC）和离线信息均相同的条件下，与先到先服务（FCFS）
  和分阶段方法相比，联合决策如何影响完工时间、总迟到时间、资源等待、能耗以及归一化综合目标 $J$？
\item \textbf{RQ2：}要求机器人在时域末端保留足以安全到达充电区的电量，会带来多大的性能代价？任务负载、
  充电位数量以及 A、B 两条环路之间的任务分布如何改变系统瓶颈？
\item \textbf{RQ3：}当任务只有在释放后才可见时，滚动时域方法能达到怎样的调度性能，又需要多少重规划与
  求解开销？
\end{itemize}

\subsection{贡献与报告结构}

本项目建立了一个联合调度模型，涵盖任务分配、机器人访问顺序、交叉口预约、充电位选择、充电时长和 SOC 演化。
离线 CP-SAT、滚动时域优化与启发式基线共用同一离散事件执行引擎和输出验证器。每次运行均输出任务输入、动作、
资源预约、SOC 轨迹和求解记录，使各项结果可追溯至具体决策；存档批量实验保存了每次运行的指标和求解记录。
本项目的贡献在于这种一体化建模及其在固定双环路系统上的评估。

第~\ref{sec:problem}~节定义系统、输入和范围。第~\ref{sec:model}--\ref{sec:impl}~节给出模型、求解方法和
系统实现与验证。第~\ref{sec:setup}--\ref{sec:conclusion}~节介绍实验、分析结果、讨论局限并给出结论。附录给出完整模型、
算例的任务列表与调度记录，以及关键代码节选。

\section{问题定义}

\subsection{网络与资源配置}

系统包含两条连接关系固定的单向环路（图~\ref{fig:network}）。环路 A 为 X $\to$ A1 $\to$ A2 $\to$ A3
$\to$ A4 $\to$ WA $\to$ X，环路 B 为 X $\to$ B1 $\to$ B2 $\to$ B3 $\to$ B4 $\to$ WB $\to$ X。机器人 R1 和 R2
只服务环路 A，R3 和 R4 只服务环路 B。WA 和 WB 是共享交叉口 X 前的等待点。充电支路为 X $\to$ H $\to$ C1/C2
$\to$ H $\to$ X，其中 H 是充电缓冲与排队位置，C1 和 C2 是可配置的充电位。

几何意义上的避碰。

\subsection{范围与假设}
\label{sec:scope}

\begin{itemize}
\item \textbf{车队与网络。}四台机器人（每条环路两台）、一个共享交叉口、最多两个充电位；每项任务都是单一
  环路内的取送订单，机器人一次只携带一项任务。实验使用 20--60 项任务。
\item \textbf{互斥资源。}X 和每个启用的充电位同一时刻只容纳一台机器人，相邻两次通过之间留有安全缓冲。
  机器人只在 WA、WB 或 H 排队等待 X 或充电位，不得停在 X 内，也不得在被占用的充电位内排队。
\item \textbf{时间与能量。}各项时长是确定的。SOC 随移动、装卸、排队和线性充电变化；任务之间断电待机不耗电。
  任务、通过交叉口和充电访问均不可抢占，充电结束后机器人立即离开充电位。启发式规则充到 95\pct，
  CP-SAT 则自行选择充电量。
\item \textbf{信息条件。}启发式规则和离线 CP-SAT 可以看到完整任务表，但不会在释放前开始任务；滚动 CP-SAT
  只看到已释放的任务，并保持已提交的动作不变。手动命令回放只执行和检查外部计划，不参与算法比较。
\item \textbf{不在范围内。}非线性充电、多个交叉口、可变车队规模、连续运动学和避障。机器人无需返回起点；
  末端储备只保证最后一项任务之后仍能到达充电位。
\end{itemize}

\subsection{分配与时序约束}

模型引入虚拟初始顶点，通过 \code{AddCircuit} 约束对每台机器人获配的任务和可选充电访问进行排序。任务顶点当且仅当
任务被分配时激活；充电顶点在该访问启用时激活。未激活的顶点使用自环，虚拟初始顶点的自环表示机器人闲置。
分配、弧、激活和充电位变量均为二元变量。被选中的弧满足
\begin{equation}
\sum_{k \in K_i} x_{ik} = 1, \qquad s_i \ge r_i, \qquad
a_{kab} = 1 \;\Rightarrow\; s_{kb} \ge f_{ka} \quad (b \ne 0).
\label{eq:assign}
\end{equation}
其中 $s_i$ 包含空驶至取货点的时间，$c_i$ 为卸货完成时间，$f_{ka}$ 为前一个访问的结束时间。若任务 $i$ 分配给
机器人 $k$，其完成时间满足式~\eqref{eq:completion}：空驶时间由所选前驱顶点决定，载货行驶沿固定的取送路线进行，
求和项累加集合 $\mathcal{R}_{ki}$（所选空驶和载货路径上的交叉口通行）中允许的资源排队时间。闭合到虚拟顶点
的弧不含返程行驶，因此完工时间止于最后一次送达。
\begin{equation}
c_i = s_i + \tau^{\text{empty}}_{ki} + L_i + \tau^{\text{loaded}}_{i} + U_i
  + \sum_{r \in \mathcal{R}_{ki}} w_{kr}.
\label{eq:completion}
\end{equation}

\subsection{资源容量与电池安全}

每次选中的交叉口通行都在同一个 \code{NoOverlap} 约束中预约区间 $[e_{kr},\, l_{kr} + \delta)$，其中 $e_{kr}$
和 $l_{kr}$ 为进入和离开时间，$\delta = 2\beta$；默认缓冲参数为 2\,s，因此相邻两次通行之间间隔 4\,s。
这是对交叉口的按时间预约，思路与自动驾驶车辆基于预约的交叉口管理~\cite{dresner2008} 相同。机器人在 WA、
WB 或 H 等待，不得停在 X 内。

每次选中的充电访问先在 H 排队，进入一个选定的充电位，不间断地充电，然后立即返回 H；充电位区间同样互不
重叠。充电位选择满足 $\sum_{p} b_{kqp} = y_{kq}$。设到达 H 的时间为 $h$，则充电开始于
$u = h + w^{C} + \tau_{Hp}$，访问结束于 $u + D + \tau_{pH}$。充电量和充电时长都是决策变量，这与充电位数量有限时
采用灵活充电策略的 AGV 调度~\cite{li2025chargers} 以及将充电时长作为决策变量的模型~\cite{li2025battery}
一致；启发式规则则固定充到 95\pct。

SOC 随移动、装卸和资源排队而下降，任务之间的断电待机不耗电。对于不含充电、包含 $n_h$ 次装卸的路段，
\begin{equation}
S_{\text{out}} = S_{\text{in}} - \sum_{(u,v)} g_{uv} - n_h\, g_h - \rho_w \sum w ,
\label{eq:soc}
\end{equation}
系统在充电前以及每个动作之后校验该式，并要求电量保持在 $[S_{\min}, 100]$ 之内。对于到达 H 时 SOC 为 $S^{H}$、排队时间为
$w^{C}$、充电时长为 $D$ 的充电访问，安全到达、补电和离开要求
\begin{equation}
S^{-} = S^{H} - \rho_w w^{C} - g_{Hp} \ge S_{\min}, \qquad
S^{+} = S^{-} + \rho_c D \le 100, \qquad
S^{+} - g_{pH} \ge S_{\min}.
\label{eq:charge}
\end{equation}

默认的末端储备要求每台执行过任务的机器人在最后一次送达后保留足够电量，以便到达充电位并承受保守估计的排队，
其中包含为其他三台机器人各一次充电预留的余量；整数模型额外加 0.5 个百分点的余量，解码后的计划还要对照实际
预约日历检查。消融版本 \code{cpsat-nores} 仅移除这一末端储备要求，仍保留执行过程中的电池安全约束；由于可行域更大，
该版本予以单独评估。滚动时域优化则始终保留末端储备。

\subsection{目标函数与模型范围}

优化器最小化由完工时间、迟到、等待和能耗组成的综合目标。记 $T_i = \max(0,\, c_i - d_i)$、
$C_{\max} = \max_i c_i$，交叉口和充电的总排队时间为 $W_X$ 和 $W_C$，正能耗总量为 $E$，则
\begin{equation}
\min\ J = \frac{1}{4}\left( \frac{C_{\max}}{\hat R_C} + \frac{\sum_i p_i T_i}{\hat R_T}
  + \frac{W_X + W_C}{\hat R_W} + \frac{E}{\hat R_E} \right).
\label{eq:J}
\end{equation}
能耗与延误一同进入目标函数，这与多载 AGV 的多目标调度中兼顾装卸延误与能耗的做法~\cite{huo2024multiload} 类似。
参考值通常取同一实例上 FCFS 的结果，分母下限分别为 1\,s、60\,s、60\,s 和 1 个 SOC 百分点。若 FCFS 失败，
则依次尝试分阶段和截止时间优先，最后才只用下限作为参考值；因此 FCFS 的得分不一定恰好为 1。能耗不计补电，
加权迟到与 CSV 中未加权的 \code{total\_tardiness} 字段不同。电池安全是硬约束，不能用目标函数中的其他项补偿。

CP-SAT 使用 1\,ms 的时间网格、保守的整数近似和有限数量的可选充电时段。状态 OPTIMAL 仅针对这一有界整数模型而言；
在时限内得到的可行解并不构成物理意义上的全局最优证明。所有候选解均须经过解码和验证，且回退方案不会
继承求解器的最优性证明。

\subsection{基线策略与联合贪心调度}

SOC 低于 20\pct\ 时先充电再执行任务；接受的任务还必须通过完成检查和末端储备检查。

策略 & 决策规则 & 比较目的 \\
\midrule

\label{fig:pipeline}
\end{figure}

联合贪心按释放时间顺序考虑最多八项待处理任务及两台可执行的机器人。每个候选方案都在状态副本上评估：尝试执行
该任务，检查任务后的储备，必要时预先插入充电。不可行的候选会被丢弃，不影响已提交的调度。算法选取使局部得分
\begin{equation}
\text{score}_{ik} = c_i + 3\, p_i T_i + 0.5\, \Delta W_i + 2\, \Delta E_i
\label{eq:score}
\end{equation}
最小的候选方案，得分相同时按任务和机器人编号打破平局；增量等待 $\Delta W_i$ 和正能耗 $\Delta E_i$ 包含插入的充电访问。该得分使用
原始单位和固定系数，而不是归一化的 $J$。它能快速给出联合初始调度，但受限于前瞻视野，不能保证得到最优的完整调度。
各启发式规则均可访问完整任务列表（实际执行仍不早于释放时间），因而属于离线对比基线，而非与滚动时域方法信息条件
相同的在线基线。若没有候选通过检查，策略会报告未找到安全计划，但这并不证明不存在可行调度。此外，也可采用基于学习的调度器
（例如 Chang 等~\cite{chang2025rl} 的分层强化学习调度方法）；本项目保留显式规则，以便每个决策
都能对照约束进行检查。

\subsection{离线联合优化}

机器--AGV 集成调度既有混合整数规划模型~\cite{yao2025milp}，也有显式处理运输任务是否存在的约束规划模型
~\cite{yao2026cp}。本项目同样仅在访问被选中时将其激活，并采用 Google OR-Tools 的 CP-SAT 求解器~\cite{cpsat}
求解模型。CP-SAT 融合了惰性子句生成、线性松弛以及包括大邻域搜索在内的并行组合搜索~\cite{perron2023cpsat}，
十分契合本问题：任务分配与访问选择均为布尔变量，可选区间、\code{AddCircuit} 和 \code{NoOverlap}
可以直接表达访问顺序和资源容量，而线性的时间与 SOC 约束则将这些选择与可行执行联系起来。联合贪心提供初始物理调度；
当该调度可投影至时间网格上时，还作为 \code{AddHint} 搜索提示，引导搜索但不固定决策。有效的初始调度同时独立保存在
求解器之外。

求解所得回路通过仿真器的规划器解码，使用模型给出的访问顺序、通行时间、充电位和充电目标。实际时长和 SOC
变化根据地图重新计算，而不是直接取自整数变量；解码器还会检查生成的动作和启用的末端储备。最终返回的计划取有效
解码候选与合格启发式初始解中实际 $J$ 较低者；这只保证不劣于所保留的联合贪心初始解，而不是不劣于所有基线。

求解状态、界、间隙（gap）、解码后的目标值和回退原因分别保存。FEASIBLE 表示整数模型有候选解；成功回退
既不是已证明的最优，也不是运行失败。UNKNOWN 表示在预算内既未证明可行也未证明不可行；INFEASIBLE 只针对
有界整数模型，MODEL\_INVALID 表示实现错误。这些状态与返回的物理调度的验证结果分开记录。总运行时间包括
初始规划、建模、求解、解码和验证，而求解器墙钟时间只覆盖搜索。在受墙钟时间限制的并行搜索中，固定随机种子
并不能保证结果逐位复现；存档实验的预算见第~\ref{sec:setup}~节。

\subsection{滚动时域优化}

在决策时刻 $t$，滚动时域优化仅可获取已释放且未提交的任务。与仓储 AGV 动态任务的滚动分配~\cite{xin2024dynamic}
类似，计划随信息到达而重新计算：默认每 60\,s 一次，窗口约为每台机器人 600\,s 的工作量。任务按截止时间、
优先级和编号排序。窗口限制的是考虑的工作量，而不是完成期限：前往取货点的行驶、排队或充电都可能使计划超出
窗口。机器人当前状态和已提交的预约构成下一次求解的初始条件。已有研究同样采用滚动时域再优化在执行过程中调整 AGV
通过共享交叉口的先后顺序~\cite{berndt2024receding}，这与本文滚动时域方法修正通行时隙和充电时隙的方式相近。

每台机器人仅提交在下一个决策时刻之前启动的访问前缀。已提交的访问整体冻结，包括延续到该时刻之后的
动作和预约；执行中的任务和充电不会被中断，未提交的任务之后仍可重新分配。每次求解都用当前已知的任务和状态
进行归一化；全实例参考值只用于事后评分，因此未释放的订单既不影响当前决策，也不影响目标系数。局部求解器的界
不构成在线全局最优的证明。

\caption{一次本地运行中的滚动时域提交，决策时刻为 60\,s 和 120\,s。第一轮提交的访问在下一个决策时刻之后
仍保持冻结。}

\subsection{共享执行与可追溯性}

LoopLab 由 Python 后端和浏览器回放前端组成。\code{simulator.py} 维护机器人状态、预约日历、动作生成、指标和

\section{实验设置}
\label{sec:setup}

\subsection{评估问题与数据生成}

RQ1 评估联合调度相对分阶段方法和单一规则基线能否改善完工时间、迟到、等待和能耗；RQ2 考察末端储备和资源
敏感性；RQ3 考察在线求解质量和重规划开销。实验使用针对四机器人双环路系统生成的合成任务。

对于 $n$ 项基础任务，释放时间在 $[0, 12n)$ 秒内以 10\,s 为步长均匀抽样。取货站和送货站互不相同且位于同一
环路。装货和卸货各取 10、15 或 20\,s，截止时间为释放时间加 480--900\,s。优先级 1、2、3 的概率分别为
50\pct、25\pct\ 和 25\pct。紧急订单和每台机器人 50--100\pct\ 的初始 SOC（保留一位小数）由独立的随机流生成，
因此加入紧急订单不会改变基础工作负载。

合成数据代表反复出现的运输调度决策，而非工厂实测数据：同环路订单符合固定导轨布局；释放时间形成相互竞争的请求；
装卸时长和截止余量改变工作量和紧迫程度；不同的初始 SOC 产生充电需求。这些数值范围是实验假设，未经运营
数据校准，因此结果只支持本仿真器内的受控比较。

\subsection{指标、统计与公平比较}

指标包括 $J$、完工时间、未加权和按优先级加权的迟到、迟到任务比例、资源等待、能耗、充电次数、运行时间和
违反数。平均资源等待为 $(W_X + W_C)/|I|$，不含断电待机；能耗为正的 SOC 消耗之和，不计补电。表格按需
报告均值和样本标准差；本地图表显示中位数和各随机种子的结果。成对目标降幅为 $1 - J_s / J_{\text{FCFS}}$，
正值表示改进；它使用 FCFS 的实际 $J$，由于分母下限，该值可能小于 1。

启发式规则和离线 CP-SAT 预知未来任务但遵守释放时间，而滚动时域方法仅获知已释放的任务，并在最终评估之前用已知
任务归一化。主要比较均保留末端储备；无末端储备的 CP-SAT 仅作为消融实验。启发式规则固定充到 95\pct，CP-SAT 自选
充电量，因此所得改进并未单独分离出充电灵活性的影响。可行解不代表最优，保留初始解也不等于失败。全部 700 条存档记录
均报告成功且违反数为零；尚未进行统计显著性检验。

\section{结果与分析}
\label{sec:results}

存档实验提供了第~\ref{sec:setup}~节所述的 10 个种子、7 种策略的比较。本地图表使用 3 个种子、4 种配置和
5 种离线策略，共 60 次运行，另有一个包含 FCFS、CP-SAT 和滚动时域计划的独立 12 任务算例。存档实验提供总体比较，
本地轨迹用于解释具体决策；二者的预算和版本不同，因此不合并样本。

\subsection{在线重规划}

在本地 12 任务输入上，滚动时域 CP-SAT 进行了 18 次重规划，没有发生回退。总运行时间为 5.40\,s，其中求解器墙钟
时间为 5.10\,s；完工时间为 1\,237.6\,s，$J$ 为 0.505。其完工时间虽晚于离线 CP-SAT，但只能在任务释放后获取
任务。存档基础设置下的平均 $J$ 为 0.636，同样介于 FCFS 与离线 CP-SAT 之间。这些比较描述的是信息受限条件下
的运行表现，无法将算法本身的求解质量与对未来信息的掌握区分开；仅凭总运行时间也无法确定最坏情况或第 95 百分位的
重规划延迟。

\section{讨论}
\label{sec:discussion}

\subsection{结果解读}

存档实验和本地实验都表明，在所测试的系统中，对任务分配、交叉口预约和充电决策进行联合调度确有裨益。联合贪心
相对 FCFS 将平均综合目标降低 20.7\pct，并通过协调的资源与电量检查给出可行调度。离线 CP-SAT 在存档的搜索
预算下取得了进一步改进，但这一改进不能完全归功于求解器，因为 CP-SAT 还允许灵活的充电量。

算例轨迹揭示了一个具体瓶颈：固定充到 95\pct\ 可能长时间占用充电位，进而推迟其他机器人的作业。部分充电和任务重排
可以减少这种延误，但二者各自的贡献尚未分离。

短预算结果也说明了计算限制的重要性：CP-SAT 可能直接返回经过验证的联合贪心调度而没有改进。因此，联合贪心
是实用的初始解和回退方案，而在搜索时间充足时，CP-SAT 能够提升调度质量。解读结果时应依据实测的目标值、
资源排队和计算时间，而不仅仅是求解器的状态标签。

\subsection{局限性}

结果只适用于本文所考虑的四机器人固定路线系统和合成工作负载。验证表明调度满足所建模的资源与电池约束，但
不能证明一般意义上的避碰（这需要如文献~\cite{li2024conflict} 那样的运动层冲突模型），也不能证明物理部署的
安全性。

启发式规则使用固定的充电目标，而 CP-SAT 允许灵活的充电量，因此无法分离充电灵活性与任务重排各自的作用。
此外，离线方法预知未来任务，而滚动时域 CP-SAT 仅掌握在线信息，因此二者无法在相同信息条件下直接比较。模型假设电池充放电行为确定且
呈线性；若考虑能耗的不确定性，需要引入随机模型，例如 Ricard 等~\cite{ricard2026chance} 针对电动公交提出的机会约束电池管理。

最后，存档实验与本地实验在硬件、代码版本和求解预算上都不同。存档研究每种配置使用 10 个种子，本地检查只用
3 个，且未进行正式的显著性检验。要分离各项调度决策的影响，还需要更受控的比较。

%==================================================================================================
\section{结论}
\label{sec:conclusion}

本项目针对固定双环路系统实现了任务、交叉口与充电的联合调度。在存档基础实验中，保留末端储备的 CP-SAT 相对 FCFS
将平均 $J$ 降低 53.2\pct，完工时间缩短 28.3\pct。本地算例表明，更短的调度伴随着更少的充电位占用与排队，
而短预算批量检查没有发现超出联合贪心的改进，说明求解预算与调度模型同样重要。

末端储备以有限批次内的性能换取全部任务结束后仍能安全前往充电。滚动时域规划在冻结已提交动作的前提下处理已释放的任务，但要
公平地对在线方法排名，仍需要信息条件相同的基线。现有证据支持所测试的合成系统及其资源规则；更广泛的交通
安全、实时性保证和工厂部署还需要进一步的建模与测量。

\section{完整模型}
\label{app:model}

实现中使用 $V_k = \{0\} \cup I_k \cup Q_k$，其中 $I_k$ 为机器人 $k$ 所在环路上的任务集合，$Q_k$ 为其可选充电时段。任务的存在变量为 $z_{ki} = x_{ik}$，充电访问为
$z_{kq} = y_{kq}$，且 $z_{k0} = 1$；分配 $x$、弧 $a$、激活 $y$ 和充电位 $b$ 均为布尔变量。下列各式以秒和
SOC 百分点为单位；在内部，时间变量是 $[0, \bar H]$ 内的整数刻度，节点 SOC 和充电目标位于 $[U S_{\min}, 100U]$ 内。
虚拟初始状态固定了初始可用时间、位置和 SOC。
\begin{equation}
\sum_{k:\, i \in I_k} x_{ik} = 1, \qquad a_{knn} = 1 - z_{kn} \quad (n \ne 0), \qquad
\textsc{Circuit}(a_k).
\end{equation}
每条被选中的非自环弧都属于经过顶点 0 的唯一回路，虚拟初始顶点的自环表示机器人闲置。被选中的弧 $a \to n$（$n \ne 0$）
要求 $s_{kn} \ge f_{ka}$，并计入前往取货点或 H 的固定入向行驶。任务副本在被选中时共享 $s_i, c_i$，且
$s_i \ge r_i$；装货、载货行驶和卸货按等式约束依次推进时间。未激活访问的时间为零，未激活的通行与充电等待也为零。
充电访问按顺序使用：$y_{k,q+1} \le y_{kq}$，当 $y_{k,q+1} = 1$ 时 $s_{k,q+1} \ge f_{kq}$。禁止从充电访问直接连到虚拟终点的弧；
从任务连到虚拟终点的闭合弧不含返程行驶。
\begin{gather}
e = \text{arrival} + w, \qquad l = e + \tau^{X}_{kr}, \qquad \textsc{NoOverlap}\{[e,\, l + \delta)\}, \\
\sum_{p} b_{kqp} = y_{kq}, \qquad u = h + w^{C} + \tau_{Hp}, \qquad f = u + D + \tau_{pH}, \\
S^{-} = S^{H} - \rho_w w^{C} - g_{Hp} \ge S_{\min}, \qquad S^{+} = S^{-} + \rho_c D \le 100, \qquad
S^{+} - g_{pH} \ge S_{\min}.
\end{gather}
其中 $\tau^{X}_{kr}$ 为该次通行驶入 X 的边的行驶时间。资源排队只发生在 WA、WB 或 H，绝不在 X 内。充电等式只对选中的充电位生效，其可选区间加入该充电位的
\code{NoOverlap}。以刻度计，启用的 $D$ 介于 1 与 $\lceil 100U/\alpha \rceil$ 之间，其中
$\alpha = \lfloor \rho_c U / T \rfloor$。在每条被选中且不含充电的路径上，
$S_{\text{out}} = S_{\text{in}} - \sum g - \rho_w \sum w$（含装卸）。冻结的预约是强制的。最后一次送达后必须
在安全下限之上保留前往充电位的能耗、$3(95 - S_{\min})\rho_w/\rho_c$ 以及 0.5 个百分点的余量；解码时还会检查
实际可达性。
\begin{equation}
\min\ J = \frac{1}{4}\left( \frac{C_{\max}}{\hat R_C} + \frac{\sum_i p_i T_i}{\hat R_T}
  + \frac{W_X + W_C}{\hat R_W} + \frac{E}{\hat R_E} \right), \qquad C_{\max} = \max_i c_i .
\end{equation}

归一化分母取 FCFS 各分项，并以 $(1, 60, 60, 1)$ 为下限；$E$ 不计补电。滚动时域求解保留已固定的历史贡献，只用
已知任务归一化。取 $T = 1000$ 刻度/秒、$U = 60\,000\,000$ SOC 单位/百分点，时长、释放时间、能耗和排队耗电
向上取整，截止时间、初始 SOC 和充电增量向下取整。不在网格上的路径在每次通过交叉口或前往充电位时额外计入
20 个刻度的耗电作为模型保护；这部分计入模型中的 $E$，但不出现在解码后的动作中。访问时间上界为
$\bar H = \lceil T\,[\,t_0 + (|I| + 8)(20\,\tau_{\max} + 5000)\,] \rceil$，其中 $t_0$ 为最晚的初始时间或
释放时间，$\tau_{\max}$ 为最长的边行驶时间。机器人 $k$ 拥有 $\max(q_k^{\text{hint}},\, 1,\, \lfloor |I_k|/5 \rfloor)$ 个充电时段，其中 $q_k^{\text{hint}}$ 为联合贪心初始解中机器人 $k$ 的充电次数；显式上限
也会约束回退方案。返回有效解码候选与可接受的联合贪心计划中实际 $J$ 较低者；二者都不可用时运行失败。
OPTIMAL 指的是这一有界整数模型。

\paragraph{交叉口预约。}\code{optimizer.py} 中的 \code{JointModel.path} 将被选中的一次通过转换为可选区间，
其长度为 $\tau^{X}_{kr} + \delta$（即代码中的 \code{dt + self.gap}）；未激活访问的进入时间和等待均为零。随后每种
资源各用一个 \code{NoOverlap}，保证 X 和每个充电位的容量。
\begin{lstlisting}
wait, entry = self.var('w_cross'), self.var('e_kr')
self.model.add(entry == at + wait).only_enforce_if(use)
self.model.add(entry == 0).only_enforce_if(~use)
self.model.add(wait == 0).only_enforce_if(~use)
self.resources['X'].append(self.model.new_optional_fixed_size_interval_var(
    entry, dt + self.gap, use, 'X'))
...
for intervals in self.resources.values():   # X, C1, C2
    m.add_no_overlap(intervals)
\end{lstlisting}

\paragraph{解码与安全回退。}CP-SAT 的解先经规划器重放和验证，启用末端储备时还需满足该要求，再按实际目标值与联合贪心初始解比较；否则保留
初始解并记录原因。
\begin{lstlisting}
decoded = joint.decode(solver)             # replay through Planner
build_result(decoded, base.results + tasks, 'cpsat',
             started, opts['norm'])        # independent validation
if opts['terminal_reserve']:               # robots active in this solve
    for k in active:                       # (index set abridged)
        decoded.ensure_reserve(k)          # charger reachable at end
if (selected is None or score(decoded, opts['norm'])
        <= score(selected, opts['norm']) + 1e-7):
    selected = decoded
else:
    metadata['fallback'] = 'joint hint has a lower decoded objective'
\end{lstlisting}
